# Patterns Guide

This folder is the second learning layer of the project.

## Why This Folder Exists

The goal is to stop solving every problem as a brand-new problem.
Instead, learn the reusable pattern first, then map many problems to that pattern.

## Naming Rule

Every pattern class now follows this format:

- `PT<number><DescriptiveName>`

Examples:

- `PT1FrequencyMapTemplate`
- `PT2VariableWindowTemplate`
- `PT5KnapsackTemplate`

This gives you both:

- a strict beginner-friendly study order
- a descriptive class name that still tells you what the pattern actually does

## How To Study A Pattern Folder

1. Start with `PT1` in that folder.
2. Read the class comments slowly.
3. Run the matching `Main` file.
4. Pause at each key variable in the debugger.
5. Read the folder `README.md` and match the pattern to problem types.
6. Then move to the next PT variation.

## What These Pattern READMEs Tell You

Each pattern folder explains:

- what kind of LeetCode problems belong there
- how to identify the pattern from the question text
- which PT variation to use first
- example LeetCode problem families for each variation
- common mistakes beginners usually make
